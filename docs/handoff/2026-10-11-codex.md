## Architecture decision (owner, Room #1540)

- The existing universal client API stays as is: `POST /v1/jobs?capability=…` with `ChatRequest`
  (`routes/proxy.py:83`), pin validation (`proxy.py:183` → `providers/catalog.py:80`), catalog via
  `GET /v1/models`, chains and their policies unchanged.
- Subscription models are added to the catalog as `claude-sub/<id>` and `codex-sub/<id>`, selectable
  ONLY by explicit pin (not in any chain); the broker routes them internally to the CLI worker (same
  billing guard, attestation, lease, project allowlist + policy). `/v1/agent/runs` stays an internal /
  diagnostic API.
- Explicit model never silently substituted (never pass `--fallback-model`). Quota → wait or error, no
  paid fallback.
- Honest capability errors for what the CLI route can't do (tools, stream, image input). GPT-image via
  Codex only as a real decodable PNG artifact through the image contract — never placeholder text.
- Access: allowlist projects only (default). Opening to every broker client is an owner/dot decision
  (subscription terms: personal use, not a shared backend).
- Plan (accepted): a) registry providers claude-sub/codex-sub (seed `claude-sub/claude-sonnet-5-5`,
  more via a setting; pricing = subscription, cost null); b) `/v1/jobs` with such a pin → agent lane,
  messages → prompt, CLI with no tools; c) normal job result shape, response_format json validated
  (InvalidJSON, no swap); d) 400 unsupported_for_subscription_model for tools/stream/images;
  f) full regression + fake-CLI tests. `codex-sub` disabled until Codex isolation is approved.

## Codex sandbox — NOT APPLIED

- Diagnosis: Codex's bwrap sandbox can't start in the hardened container. Barrier 1 is Docker's
  default seccomp (userns denied); barrier 2 is AppArmor `docker-default` (mount denied).
  sysctl allows userns (`kernel.unprivileged_userns_clone=1`).
- Proposal (static in `1817155`, NOT applied): only `agent-worker-codex` gets
  `security_opt: [no-new-privileges:true, seccomp=<codex-seccomp.json>, apparmor=aibroker-codex]`;
  keeps cap_drop ALL, read_only, no privileged, no docker.sock, network `agent_db` only.
  The AppArmor profile must be loaded by the operator (`apparmor_parser -r`).
- Needs: an independent review, then the OWNER's explicit approval (security-sensitive).
- STOP rule: no runs with `seccomp=unconfined` / `apparmor=unconfined`, not even throwaway.
- Imagegen in headless `codex exec`: tool `image_generation` is stable/on in 0.162.1; output path and
  `--json` event for images unverified; PNG export is done by the worker process (never the model).
